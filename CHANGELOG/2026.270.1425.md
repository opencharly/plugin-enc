# 2026.270.1425 — fix(plugin-enc)!: ship a self-contained CUE schema (no schema-less plugin)

## Summary

Restore `plugin-enc`'s **own self-contained CUE schema** — the schema-less-plugin R5 cutover
tracked in **opencharly/charly#712** (the SDK contract landed as
**opencharly/sdk#314**). `NewMeta` passed a `nil` schema FS and served an **EMPTY**
schema — the SDK's former *"input-less plugin"* waiver. There is no schema-less plugin:
every plugin presents the same CUE declaration surface, even where a capability's authored
input is its pass-through CLI grammar (or a structured wire envelope) rather than an
authored `plugin_input`.

### Files

- `candy/plugin-enc/schema/enc.cue` — **NEW** (this PR): the plugin's self-contained schema (`#EncPlugin`), documenting `verb:enc`. It references no base def, so it compiles **standalone** and splices `base ++ plugin` at the host load gate (`charly/charly/plugin_loader.go` `registerPluginUnitSchema`).
- `candy/plugin-enc/enc.go` — **modified**: `//go:embed schema/*.cue` + `sdk.NewMeta(calver, caps, schemaFS)` replaces the trailing `nil`; the stale comment (which claimed only the trivial `#EncInput` ships so the host's plugin-schema gate has a non-empty, base-spliceable schema) is corrected in place.
- `candy/plugin-enc/schema_serve_test.go` — **NEW** (this PR): `Describe` MUST serve a non-empty `schema_cue` carrying `#EncPlugin` (fails without the change).
- `schema_splice_test.go` (alongside `candy/plugin-enc/schema/enc.cue`) — **NEW** (this PR): executes the REAL host gate (see §1; negative control §2).
- `candy/plugin-enc/go.mod` — **modified**: promotes `cuelang.org/go` from `// indirect` to a direct require (the new splice test imports `cuelang.org/go/cue` + `cuecontext`).

**Refs:** opencharly/charly#712
